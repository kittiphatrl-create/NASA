## ขอบเขตและส่วนที่ล็อกไว้

- **เมนูที่เปิดด้วย M ถูกยกเว้นทั้งชุด** เก็บหน้าสถานะ ภารกิจ และของ รวมถึงข้อมูล ข้อความ ชื่อแท็บ สี ฟอนต์ กราฟิก ขนาด โฟกัส อินพุต และแอนิเมชันเปิด–ปิดกับพลิกหน้าไว้ตามที่อนุมัติ หลีกเลี่ยงการแก้ตัวช่วยหรือค่ากลางที่เปลี่ยนผลในสมุด หากต้องแก้ UI ในไฟล์ที่แชร์กับ M ให้จำกัดที่ตัวเรียกหรือส่วนของหน้าจอเป้าหมาย
- **บทพูดตัวละครไทยและอังกฤษคงข้อความเดิมทุกบรรทัด** ปรับกล่อง ป้ายชื่อ ฟอนต์ การตัดบรรทัด จังหวะพิมพ์ เสียง และสไปรต์ได้ ไฮไลต์คำสำคัญด้วยการจัดรูปแบบจากข้อความเดิม เก็บผู้พูด ลำดับ ประโยค เงื่อนไข และผลของบทสนทนาเดิม ข้อความในคลิปเป็นตัวอย่างการจัดวาง
- ตรวจและปรับ **UI ที่ผู้เล่นพบในเส้นทางหลักนอกเมนู M ทั้งหมด** รวมถึงหน้าเริ่มเกมและไปต่อ วิธีเล่น ป้าย E และการโต้ตอบ ภารกิจนอกสมุด คำเตือน ช่วงอพยพ คอนโซลและเครื่องจักร แผนไฟ คลังหรือรายการที่เปิดแยกจาก M หน้าจัดมื้อเย็น หน้าพัก ตั้งค่า และผลลัพธ์ ตรวจบทเปิดและบทจบที่ใช้ UI ร่วมด้วย
- ผูกทุกปุ่ม สถานะ ต้นทุน เวลา และทรัพยากรกับข้อมูลจริง รักษากติกาเกม เซฟ ความคืบหน้า ทางเข้าหน้าจอ และคำสั่งที่ผู้เล่นใช้เดิม เก็บงานค้างของผู้ใช้แล้วแก้เส้นทางแสดงผลที่ใช้งานจริง

## บทสนทนาแบบในคลิป

- ใช้ **สไปรต์เดิมของผู้พูดแต่ละคน** ตามระบบเกม ขยายประมาณหนึ่งในสามจากหน้าบทสนทนาเดิมเมื่อพื้นที่พอ รักษาสัดส่วน สี และขอบพิกเซล ใช้การขยายแบบ nearest-neighbor จัดสไปรต์ชิดมุมล่างฝั่งผู้พูดและให้หน้ากับส่วนสำคัญยังเห็นครบ ใช้ฝั่งเดิมของ NPC และตัวผู้เล่น เมื่อไม่มีภาพให้คืนพื้นที่แก่ข้อความ
- ให้เห็นฉากจริงที่หรี่แสงด้านหลังสไปรต์เหมือนคลิปฉบับอนุมัติ เว้นพื้นที่รอบสไปรต์ให้โปร่ง ใช้ขอบพิกเซลเดิมของตัวละคร ห้ามนำแผ่นรองสีเขียวหรือเงาซ้อนแบบที่ตัดออกกลับมา
- วางกล่องบทพูดแนวนอนช่วงล่าง พื้นครีม กรอบเขียวอมฟ้ามุมตัด ขอบหมึกเข้ม ป้ายชื่อสีอำพันแยกจากพื้นที่อ่าน และมีมุมชี้ไปฝั่งผู้พูดตามคลิป เว้นขอบข้อความเพื่อให้สระบนและสระล่างอ่านได้ และกันที่สำหรับคำสั่งไปต่อ โดยเฉพาะเมื่อหน้าต่างเล็กหรือใช้ตัวอักษรขนาดใหญ่
- ข้อความหลักใช้ **Titan Gate UI Regular** ป้ายชื่อและคำสำคัญใช้ **Titan Gate UI Bold** เน้นเฉพาะคำที่ช่วยให้เล่นต่อ เช่น ชื่อจุดหมายหรือสิ่งที่ต้องโต้ตอบ เก็บบทพูดครบและแบ่งบรรทัดตามความหมาย ถ้าข้อความยาวให้จัดพื้นที่หรือแบ่งส่วนแสดงผลโดยรักษาลำดับและเงื่อนไขเดิม
- แสดงคำสั่ง **Enter · ต่อ** เมื่อพิมพ์ครบ รองรับการคลิกและคีย์เดิมตามพฤติกรรมปัจจุบัน กดไปต่อระหว่างพิมพ์ให้แสดงข้อความจนจบก่อน กดอีกครั้งจึงไปบรรทัดถัดไปตามกติกาเดิม

## จังหวะพิมพ์ เสียง และการสั่น

- ให้ข้อความเผยทีละกลุ่มอักขระที่อ่านพร้อมกัน รวมพยัญชนะ สระ และวรรณยุกต์ไทยในจังหวะเดียว ใช้ข้อความ Unicode ดั้งเดิมในการแบ่งกลุ่ม แล้วส่งส่วนที่แสดงผ่าน `GameUI.Thai` จัดบรรทัดให้คงที่ขณะพิมพ์และพักสั้นตามวรรค รักษาตัวเลือก **ความเร็วข้อความ** เดิมและโหมดแสดงทันที ตัวอย่างในคลิปเผยครบประมาณ 3.6 วินาทีสำหรับประโยคตัวอย่างสองบรรทัด ใช้เทียบความรู้สึกในการอ่าน
- เล่นเสียงคีย์สั้นเฉพาะเมื่อกลุ่มตัวอักษรที่อ่านได้ปรากฏ เว้นเสียงในช่องว่างหรือช่วงหยุด พิจารณาเว้นจังหวะเมื่อพิมพ์เร็วหรือหลายกลุ่มเผยในเฟรมเดียว ใช้เสียงคลิกคีย์ที่มีสิทธิ์ใช้หรือสร้างเอง และต่อผ่านระบบ `Sfx` กับค่าระดับเสียงเดิม ให้เบาพอที่จะไม่กลบเสียงเกม เมื่อกดข้ามหรือใช้การแสดงทันที ให้หยุดเสียงพิมพ์โดยไม่มีเสียงคีย์รัวตามมา
- ให้สไปรต์ขยับแนวนอนสลับเล็กน้อยและยกขึ้นนิดเดียวตามจังหวะเผยข้อความ อ้างอิงประมาณ **1–2 พิกเซลบนภาพ 1280×720** จังหวะคืนตัวราว **0.12 วินาที** ขยับเฉพาะสไปรต์ของผู้พูด กล่องบทพูด กรอบฉาก ป้ายชื่อ และข้อความอยู่กับที่ คืนสไปรต์สู่ตำแหน่งเดิมเมื่อพิมพ์จบ กดข้าม เปลี่ยนผู้พูด หรือปิดบทสนทนา
- เชื่อม **Reduced Motion** เดิมให้สไปรต์หยุดสั่นและปิดเอฟเฟกต์ขยับที่ตกแต่ง ส่วนการอ่าน คำสั่งไปต่อ และความเร็วข้อความยังทำงานตามค่าที่ผู้เล่นเลือก

## สไตล์ของ UI จุดอื่น

ใช้ภาษาภาพของกล่องบทพูดกับสมุด M ร่วมกัน กรอบเขียวอมฟ้า `#396D64`, ขอบรับแสง `#79AB95`, หมึกเข้ม `#101A18`, แผงเข้ม `#17302F`, พื้นอ่านครีม `#FFEBCA` และอำพัน `#FFB53C` สำหรับปุ่มหลัก จุดเลือก และคำสำคัญ ใช้รูปทรงมุมตัดและไอคอนเงาเข้มจากโลกของเกม ใช้พื้นสว่างหรือเข้มตามบริบทโดยให้ข้อความมีคอนทราสต์ชัด

| หน้าจอ | แนวทาง |
| --- | --- |
| ป้าย E และคำแนะนำในฉาก | ป้ายเล็กใกล้จุดโต้ตอบ กริยาและเป้าหมายอ่านได้ทันที |
| ภารกิจนอกสมุดและอพยพ | เห็นสิ่งที่ต้องทำต่อ เวลา และความคืบหน้าจริงเท่าที่จำเป็น |
| คำเตือน | ใช้หัวข้อสั้น ไอคอน และเป้าหมายที่ต้องไปเมื่อช่วยแก้สถานการณ์ |
| คอนโซลและหน้าตัดสินใจ | จัดสถานะ คำสั่ง และต้นทุนที่ต้องเปรียบเทียบไว้ด้วยกัน รายละเอียดรองอยู่ถัดจากตัวเลือกที่เกี่ยวข้อง |
| หน้าเริ่ม พัก ตั้งค่า และผลลัพธ์ | ใช้หัวข้อที่สื่อหน้าที่จริง ลำดับปุ่มชัด และวางปุ่มกลับหรือปิดต่อเนื่องกับอินพุตเกม |

ใช้ขนาดตามงาน ให้ฉากเป็นจุดสนใจระหว่างเดิน ใช้ป้ายสั้นกับการโต้ตอบ ใช้กรอบใหญ่กับหน้าที่ต้องอ่านหลายตัวเลือก ให้ปุ่มและการ์ดใช้วิธีเน้นที่สอดคล้องกัน มีโฟกัสที่มองเห็น และให้สีทำงานร่วมกับคำ รูปร่าง หรือไอคอน

## ย่อข้อความนอกบทพูด

- ถามทุกป้ายว่า **ผู้เล่นต้องรู้หรือทำอะไรจากข้อความนี้** ตัดหัวข้อรองที่ทวนหัวข้อใหญ่ คำอธิบายที่ซ้ำกับตัวเลข คำชมสำเร็จรูป ประโยคเกริ่น และคำสั่งที่ซ้ำกับปุ่ม ถ้าหนึ่งคำชัดแล้วให้ใช้หนึ่งคำ
- ใช้กริยาตรงผลของการกด เช่น “ส่งรายงาน” เมื่อส่งทันที หรือ “เปิดแผงซ่อม” เมื่อเปิดตัวเลือก ให้ภารกิจหนึ่งบรรทัดขึ้นต้นด้วยการกระทำ ระบุห้อง จำนวน หรือเงื่อนไขเฉพาะเมื่อช่วยลงมือ
- คงข้อมูลที่มีผลต่อการตัดสินใจ เช่น “ใช้อะไหล่ 1”, “ต้องมีแบต 2” หรือผลที่ย้อนกลับไม่ได้ เมื่อติดเงื่อนไข ให้บอกสิ่งที่ขาดใกล้ปุ่ม ใช้ตัวเลขจริงจากเกม
- ให้ข้อความไทยอ่านเหมือนภาษาที่คนใช้จริง อังกฤษถ่ายทอดเจตนาเดียวกัน ใช้ชื่อห้อง ไอเทม และคำสั่งเดิมทั้งเกม จัดลำดับการอ่านให้สบายตา ใช้ความหนา สีอำพัน หรือไอคอนเน้นหนึ่งจุดต่อกลุ่ม
- ตัวอย่างวิธีเขียน: “ตู้เก็บของว่างเปล่า ไม่มีสิ่งของให้เก็บในขณะนี้” → “ตู้ว่าง”; “โปรดเดินทางไปยังห้องสื่อสารเพื่อดำเนินการส่งพิกัด” → “ส่งพิกัดที่ห้องสื่อสาร”; “การซ่อมไม่พร้อมใช้งานเนื่องจากทรัพยากรไม่เพียงพอ” → “ต้องใช้อะไหล่ 1” เมื่อต้นทุนจริงคือ 1

## ฟอนต์และ Localization

- ใช้ `Assets/Resources/Fonts/TitanGateUI-Regular.ttf` กับ `TitanGateUI-Bold.ttf` **ชุดที่แก้สระและวรรณยุกต์แล้ว** ทั้งไทยและอังกฤษ ใช้ฟอนต์เดิมเพื่อให้คำอย่าง “น้ำ” และ “ที่นี่” แสดงถูกต้อง
- ใช้ `GameUI.L`, `GameUI.B` และวิธีตั้งฟอนต์ UI Toolkit เดิมที่ใช้ Advanced Text Generator ข้อความไดนามิกและข้อความบางส่วนของ Typewriter ต้องผ่าน `GameUI.Thai` ก่อนขึ้นจอ คงข้อความต้นทางเป็น Unicode ภาษาไทยปกติ
- ตัดบรรทัดและจัดไฮไลต์โดยไม่แยกกลุ่มสระกับวรรณยุกต์ ถ้า Rich Text ทำให้ฟอนต์เพี้ยน ให้ใช้ป้ายหรือ Label ชุดเดิมจัดน้ำหนักแทน ตรวจทั้ง Regular, Bold, ไทยผสมอังกฤษ และ `O₂ / CO₂`
- แก้ข้อความนอกบทพูดในระบบแปลเดิม เก็บ placeholder หน่วย และคีย์ โดยแก้ `tools/strings_src.py` หรือไฟล์ที่สคริปต์นำเข้าแล้วสร้างไฟล์ `strings.json` ใหม่ จำกัด diff ข้อความให้ตรงจุดและตรวจว่าคีย์บทพูดกับข้อความในเมนู M ไม่มีการเปลี่ยน

## สกิลและเครื่องมือ

ตรวจสกิลที่มีอยู่ก่อนใช้ ใช้ชุดนี้ตามงานและติดตั้งเฉพาะตัวที่จำเป็นและยังขาดผ่าน `skill-installer` จากแหล่งที่ทีมใช้ หลังติดตั้งให้เปิดอ่าน `SKILL.md` ตามกลไกของ Codex

- `game-ui-ux` สำหรับลำดับข้อมูล หน้าจอเกม คำเตือน และความชัดเจนขณะเล่น
- `ui-uitk` สำหรับ UI Toolkit, layout, focus, typography และการโต้ตอบ
- `unity-mcp-orchestrator` เมื่อมี Unity MCP สำหรับเปิดฉากและตรวจผลจริง ในเครื่องที่ไม่มี MCP ให้ใช้ Unity Editor, batch mode หรือตัวบิลด์
- [`ux-writing-content-design`](https://github.com/hueyexe/frontend-agent-skills/tree/main/ux-writing-content-design) สำหรับไล่ตัดข้อความซ้ำ เขียนป้ายและข้อความสถานะ ตัดสินตามบริบทเกมและบทสนทนาที่ล็อกไว้
- `imagegen` เฉพาะเมื่อมีงานภาพใหม่ที่ได้รับมอบหมาย ใช้สไปรต์และส่วนประกอบ UI เดิมกับงานรอบนี้

## ตรวจงานและส่งมอบ

1. ก่อนแก้ เก็บภาพสมุด M ทั้งสามแท็บในสถานะเดียวกันเพื่อเทียบภายหลัง หลังแก้เปิดจากทั้งสองด่าน ตรวจว่าหน้าเปิดเริ่มที่สถานะ การพลิกหน้า อินพุต ฟอนต์ และข้อมูลเหมือนแบบที่อนุมัติ
2. เปิดบทสนทนาผ่านทางเข้าเกมจริง ตรวจ ORBI ตัวละครอื่น ผู้เล่น และผู้พูดที่ไม่มีภาพ ตรวจข้อความขนาดใหญ่ บทยาว สระบนล่าง ตัวหนา Typewriter เสียงคีย์ การขยับ กดข้าม กดซ้ำ สลับผู้พูด การเปลี่ยนภาษา และ Reduced Motion
3. ตรวจ UI นอกสมุดทุกกลุ่มในขอบเขตทั้งไทยและอังกฤษที่ **1280×720** และ **1920×1080** ตรวจว่าคำเตือน ภารกิจ และจุดที่ไฮไลต์เปลี่ยนตามเกม ข้อความไม่ชนขอบ และปุ่มตรงกับสิ่งที่เกิดขึ้นหลังคลิกหรือกดคีย์
4. รันชุดทดสอบที่เกี่ยวข้องและบิลด์ Windows ลงโฟลเดอร์แยกสำหรับตรวจรอบนี้ เปิดจากตัวบิลด์และจับ **คลิปจากเกมจริงพร้อมเสียง** ของบทสนทนาอย่างน้อยหนึ่งฉาก จับภาพหน้าจอ UI อื่นที่เปลี่ยน แล้วส่งพาธตัวเกม ผลตรวจ และตัวอย่างข้อความก่อน–หลังเฉพาะจุดสำคัญ
