## ก่อนแก้

ตรวจ `AGENTS.md` ถ้ามี สถานะ Git และเวอร์ชัน Unity เก็บงานที่มีอยู่ใน checkout ไว้ อ่าน `GameFlow.Menus.cs` สำหรับ `OpenPause` / `ShowSettings` / `ShowHowTo` / `ShowCardBook` ตามไปถึง Esc ใน `GameFlow.cs` และ lifecycle ของ modal ใน `GameUI.cs` ตรวจทางเข้าจากหน้าแรกใน `GameFlow.LdTitle.cs` และโหมดเก่าที่ยังเรียกหน้าเดียวกัน

ใช้ `game-ui-ux` สำหรับเลย์เอาต์และโฟกัส, `ux-writing-content-design` สำหรับป้ายและ tooltip, และ `ui-uitk` สำหรับ UI Toolkit, binding, layout และการโต้ตอบ เปิดอ่าน `SKILL.md` ของสกิลที่ใช้ ใช้ `unity-mcp-orchestrator` เมื่อมี Unity MCP สำหรับทดสอบใน Editor หากสกิลที่จำเป็นยังขาด ให้ติดตั้งผ่าน `skill-installer` จากแหล่งที่เชื่อถือได้ สกิลข้างต้นมีในเครื่องต้นทางอยู่แล้ว ใช้ภาพที่อนุมัติและภาพจากเกมเป็นทรัพยากรอ้างอิง

จำกัดการเปลี่ยนโค้ดที่หน้าทั้งสี่และทางเข้าร่วมที่เกี่ยวข้อง รักษาสมุดที่เปิดด้วย **M** ตามแบบที่อนุมัติ ทั้งข้อมูล หน้าสถานะ ภารกิจ ของ และการพลิกหน้า รักษา UI บทสนทนา คัตซีน สมดุลเกม เซฟ และคำสั่งเดิม ใช้ helper ส่วนกลางต่อเมื่อรูปลักษณ์และพฤติกรรมของหน้าที่ใช้ร่วมกันยังเหมือนเดิม

## รูปลักษณ์และจังหวะ

- ใช้ฉากจริงที่หรี่แสงหลังเปิด Pause ให้เห็นพื้นและผนังจาง ๆ เหมือน GIF วางแผงกึ่งกลางและให้พื้นที่มืดรอบแผง จากภาพ 960×540 แผงพักเกมกว้างประมาณ 56% ของจอ ส่วนวิธีเล่นและการ์ดความรู้กว้างประมาณ 76% ตั้งค่าเป็นแผงแนวตั้งสูงขึ้นและกว้างประมาณ 57% ปรับสัดส่วนตามพื้นที่จริงและขนาดตัวอักษร
- ใช้สีจาก `FieldBook` โดยตรงเมื่อทำได้ กรอบ `Teal #396D64` ขอบ `Rim #79AB95` พื้น `Paper #FFEBCA` หมึก `Ink #101A18` และรายการที่เลือก `Amber #FFB53C` ทำมุมตัด ขอบซ้อนบาง และสันกลางตามภาพหน้าที่แบ่งสองฝั่ง
- ใช้ไอคอนการ์ตูนสีอำพัน เส้นหมึก และเงาสั้นแบบ `FieldBookIcons` ใช้ไอคอนที่มีให้ตรงความหมาย เพิ่มเฉพาะไอคอนที่ขาด เช่น พัก เล่นต่อ ลำโพง คลื่นเสียง และกุญแจ แสดงสถานะสำคัญด้วยรูปทรง เครื่องหมาย หรือข้อความสั้นร่วมกับสี
- เมื่อเมาส์ชี้หรือคีย์บอร์ดเปลี่ยนโฟกัส ให้พื้นรายการเปลี่ยนเป็นอำพันและลูกศรหมึกด้านซ้ายย้ายตามรายการ ให้ข้อความในรายการใหม่เลื่อนขึ้นประมาณ 6–8 px ที่สเกลภาพ 960×540 พร้อมเงาเบลอสั้น ๆ แล้วจบเป็นตัวคมภายในประมาณ 150 ms รักษาตำแหน่งของปุ่มและรายการอื่น ใช้ตัวจับเวลาแบบ unscaled ให้ทำงานระหว่างพักเกม ถ้าชี้ข้ามหลายรายการให้จบที่รายการล่าสุด เมื่อเปิด `Settings.ReducedMotion` ให้แสดงโฟกัสแบบคมทันที
- รักษาฟอนต์ `Assets/Resources/Fonts/TitanGateUI-Regular.ttf` และ `TitanGateUI-Bold.ttf` ใช้ระบบ `GameUI.L` / `GameUI.B` / `GameUI.Txt` ตามบทบาท ป้อนข้อความไทย Unicode ให้ผ่าน `GameUI.Thai` ตามจุดสร้างหรืออัปเดต label ใช้ Advanced Text Generator แบบเดิม จัดระยะเหนือและใต้บรรทัดให้สระและวรรณยุกต์ครบ โดยเฉพาะหัว «ตั้งค่า» ที่ภาพต้นแบบวางชิดขอบ

## พักเกม

แบ่งแผงเป็นซ้าย–ขวาตาม GIF ฝั่งซ้ายใช้ไอคอนพักและคำว่า «พักเกม» ขนาดใหญ่ ฝั่งขวาเรียงปุ่ม «เล่นต่อ», «ตั้งค่า», «วิธีเล่น», «การ์ดความรู้» ในคอลัมน์เดียว แต่ละแถวมีไอคอนกับข้อความและแนวจัดวางเดียวกัน เปิดมารายการเล่นต่อเป็นสีอำพัน ใต้เส้นคั่นเป็น «เริ่มใหม่» และ «เมนูหลัก» ขอบล่างเป็นป้าย `Esc` «เล่นต่อ» จุดที่กดได้และป้ายคีย์ใช้คำสั่งเดียวกัน

- ใช้คำสั่งเล่นต่อ, `Restart()` และ `RestartToTitle()` จากเกมจริง รวมถึงเงื่อนไขการพักเกมเดิม คงความหมายของ «เริ่มใหม่» ให้ตรงการเริ่มภารกิจใหม่ตาม handler เดิม
- เปิดหน้าย่อยจาก Pause แล้วเกมต้องพักต่อเนื่อง ตลอดเวลาที่ยังอยู่ในเมนูและระหว่างย้อนหน้า กด `Esc` หรือปุ่ม «กลับ» ในหน้าย่อยให้ย้อนสู่ Pause และคืนโฟกัสให้ปุ่มเดิม กด `Esc` ที่ Pause หรือ «เล่นต่อ» จึงคืนการควบคุมเกมและ time scale ที่ควรเป็นตามสถานะเดิม
- แยกต้นทางของ Settings, How to Play และ Knowledge Cards ที่เข้าจากหน้าแรก ให้ปิดแล้วกลับหน้าแรก ใช้การเปลี่ยนหน้าในชุด modal เดียวหรือจัด lifecycle ให้ผลเท่ากัน ตรวจ callback เดิมของ `CloseModal()` ที่เปลี่ยน time scale และปุ่ม «ปิด» ที่ modal สร้างอัตโนมัติ ให้หน้าใหม่มีคำสั่งย้อนหรือเล่นต่อชุดเดียวตาม GIF และให้ modal อื่นรักษาพฤติกรรมเดิม
- รองรับคลิกและคีย์บอร์ดพร้อม focus ที่เห็นได้ กดลูกศรหรือ Tab ตามรูปแบบเมนูเกม และใช้ Enter กับรายการที่โฟกัส กรองอินพุตเดิน โต้ตอบ และปุ่ม M ระหว่างเปิด Pause ทั้งชุด

## ตั้งค่า

ใช้แผงครีมแนวตั้ง ไอคอนเรียงด้านซ้าย ส่วนควบคุมตรงกลาง และค่าที่ต้องอ่านตรงขวาตามภาพ แสดง tooltip ที่อ่านได้ทั้งเมื่อชี้และโฟกัสด้วยคีย์บอร์ด เช่น «เสียงรวม», «เอฟเฟกต์», «เสียงบรรยากาศ», «ขนาดตัวอักษร», «ความเร็วข้อความ», «ลดการเคลื่อนไหว», «เต็มจอ», «ภาษา» ผูกชื่อที่โปรแกรมอ่านหน้าจอเข้าถึงได้เท่าที่ UI Toolkit ของโปรเจกต์รองรับ วาง tooltip ให้เห็นค่ากับตำแหน่งตัวเลื่อนพร้อมกัน

| แถว | ส่วนควบคุมและแหล่งข้อมูลจริง |
| --- | --- |
| ลำโพง · เสียงรวม | หลอดลาก `Settings.Master` ช่วง 0–100% |
| ประกาย · เอฟเฟกต์ | หลอดลาก `Settings.Effects` ช่วง 0–100% |
| คลื่น · เสียงบรรยากาศ | หลอดลาก `Settings.Ambience` ช่วง 0–100% |
| Aa · ขนาดตัวอักษร | ปุ่มสามช่วง 100% / 115% / 130% ผูก `Settings.TextScale` ด้วยค่า 1 / 1.15 / 1.3 |
| มาตรวัด · ความเร็วข้อความ | ช้า / ปกติ / เร็ว / ทันที ผูก `Settings.TextSpeed` ด้วยค่า 35 / 70 / 140 / 0 ตามระบบเดิม |
| เส้นความเร็ว · ลดการเคลื่อนไหว | สวิตช์ผูก `Settings.ReducedMotion` |
| กรอบจอ · เต็มจอ | สวิตช์ผูก `Screen.fullScreen` อ่านสถานะจริงหลังสลับ |
| โลก · ภาษา | ตัวเลือกไทย / English ใช้ `ToggleLang()` และระบบแปลเดิม |

หลอดสีอำพัน ตัวจับครีมขอบหมึก และเปอร์เซ็นต์อยู่แถวเดียวกัน คลิกแทร็ก ลากตัวจับ และปรับด้วยลูกศรได้ ให้เสียงและตัวเลขเปลี่ยนทันทีผ่าน setter เดิม รักษาการบันทึกค่า `PlayerPrefs` ตามระบบปัจจุบัน ค่าเปิดหน้ามาจากการตั้งค่าของผู้เล่น ตัวอย่าง 70% → 55% ใน GIF สาธิตการลาก อัปเดตค่ากับหลอดในตำแหน่งเดิมโดยรักษา pointer capture และโฟกัส รักษาหน้าปัจจุบันกับรายการที่โฟกัสเมื่อเปลี่ยนภาษาและขนาดตัวอักษร

## วิธีเล่น

ทำหน้าคู่เหมือนภาพ ด้านซ้ายใช้ปุ่ม `WASD` และระบุลูกศรตามอินพุตจริง, `E`, `M`, `Esc` กับคำสั้น «เดิน», «โต้ตอบ», «สมุดภารกิจ», «พักเกม» ด้านขวาใช้ไอคอนยาน วิทยุ แบต ปฏิทิน และนาฬิการวมค่าที่เกี่ยวข้องกัน

- **Kestrel** ใช้เวลาจาก `_cfg.chapter1.scrambleSeconds` และขนาดถือ/ขนาดยานจากกติกาที่ช่วงอพยพใช้จริง เช่น `ScavengeInventory.CarryMax` และ `ScavengeInventory.PodMax` ใน Last Dock ตรวจ `HandSlots` เมื่อเส้นทางนั้นใช้เป็นแหล่งข้อมูล แยก «ถือ» กับ «ยานจุ» ด้วยไอคอนและคำสั้นเมื่ออาจสับสน
- **Last Dock** ใช้ config ของสถานีที่กำลังเล่น หรือ config เดียวกับที่ใช้เริ่มสถานีเมื่อยังไม่มีรัน อ่าน `signalNeeded`, `dockPower`, `days` และ `workUnits` แสดง «ส่งพิกัด», «สำรองแบต», วันกู้ภัย และช่วงทำงานต่อวัน เก็บข้อความเรื่องเดิน อ่านแผง และสลับเครื่องฟรีตามกติกาจริง
- ตัวเลข 60 วิ, ถือ 3, ยานจุ 8, พิกัด 3, แบต 2, วันที่ 7 และ 3 ช่วงต่อวันเป็นค่าที่เห็นในต้นแบบ ใช้สำหรับเทียบภาพ คงเนื้อหาวิธีเล่นของเส้นทางอื่นเมื่อผู้เล่นเข้าจากโหมดที่ใช้กติกาต่างกัน

## การ์ดความรู้

ใช้หน้าแบ่งซ้าย–ขวาเหมือน GIF ฝั่งซ้ายเลือกหมวดด้วยไอคอนและชื่อ ฝั่งขวาแสดงช่องการ์ดจำนวนที่พอดีกับหน้า ให้เลื่อนดูการ์ดส่วนที่เหลือได้ พร้อมตัวนับพบแล้ว/ทั้งหมดที่หัวหน้า ประกอบจากข้อมูลจริงดังนี้

- ใช้ `_cfg.cards` หรือ catalog ที่หน้าจริงใช้ จัดกลุ่มตาม `chapter` และคงลำดับในเกม อ่านชื่อจาก `codex.group.{chapter}` แสดงเฉพาะกลุ่มที่มีข้อมูล ใน checkout ที่ตรวจพบ 25 ใบเป็นหมวด 1 จำนวน 7 ใบ และหมวด 2 จำนวน 18 ใบ หมวดดวงจันทร์และไททันใน GIF สาธิตตำแหน่ง ใช้เมื่อเวอร์ชันที่จะทำมีการ์ดในสองหมวดนั้นจริง
- ใช้ `CardsEver()` ซึ่งรวม `Settings.CardsEver` กับ `_codex.Cards` เทียบด้วย `id` กับ catalog ปัจจุบันเพื่อหาตัวนับและสถานะแต่ละใบ รักษาประวัติการค้นพบและการปลดล็อกเดิม
- การ์ดล็อกใช้หลังการ์ดกับไอคอนกุญแจตาม GIF แสดง «ยังไม่พบการ์ด» ครั้งเดียวเมื่อยังไม่พบทั้งหมวด เก็บชื่อและเนื้อหาของใบที่เปิดแล้วจาก `card.{id}.title` และ `card.{id}.body` ให้กดเปิดอ่านเต็มและย้อนกลับมาหมวดเดิมได้ ทดสอบหมวดที่ล็อกทั้งหมด หมวดที่มีบางใบ และหมวดที่เปิดครบ

## ตรวจและส่งมอบ

1. เปิด `Main` ใน Unity แล้วเข้าจากเกมจริงใน Kestrel และ Last Dock ตรวจ Pause → ทั้งสามหน้าย่อย → Pause → เล่นต่อ รวมถึงทางเข้าจากหน้าแรก ตรวจอินพุตรั่ว การกลับด้วย Esc การคืนโฟกัส และตัวนับหรือเวลาระหว่างพัก
2. ลากหลอดในขณะที่เกมพัก ทดสอบ 0% และ 100% ปรับด้วยคีย์บอร์ด แล้วเปิดหน้าตั้งค่าใหม่เทียบค่าที่แสดงกับเสียงจริง ทดสอบภาษา ขนาดตัวอักษรทุกค่า ความเร็วทันที เต็มจอ และ Reduced Motion
3. เทียบภาพจริงกับ GIF ที่ 1280×720 และ 1920×1080 ทั้งไทยและอังกฤษ ตรวจฟอนต์ที่ 130% โดยเฉพาะ «ตั้งค่า», «วิธีเล่น» และข้อความในการ์ด ตรวจการสลับแท็บ M ก่อนและหลัง ปิดหน้าตั้งค่าแล้วลองกลับเข้าใหม่
4. ตรวจจำนวนหมวด ล็อก/ปลดล็อก และความยาวข้อความตามข้อมูลจริง ใช้โหมดทดสอบหรือเซฟทดสอบที่โปรเจกต์รองรับ รันชุดทดสอบที่เกี่ยวข้อง และส่งภาพจาก Unity ทั้งสี่หน้ากับคลิปสั้นที่เห็น hover และการลากหลอด ระบุแหล่งข้อมูลที่ผูกและส่วนที่ตรวจจริง

ใช้วิธีแปลข้อความเดิมของโปรเจกต์ เก็บ placeholder และหน่วย หากต้องแก้คีย์ใน catalog ให้แก้ต้นทาง `tools/strings_src.py` และสร้าง `Assets/Resources/Data/strings.json` ด้วยขั้นตอนเดิม ตรวจว่า diff จำกัดตามงานนี้
