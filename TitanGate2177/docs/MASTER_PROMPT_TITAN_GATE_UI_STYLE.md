# Master Prompt — สไตล์ UI และข้อความในเกม Titan Gate 2177

ใช้สมุดภารกิจ **M** เวอร์ชันแก้ฟอนต์ที่อนุมัติแล้วเป็นต้นแบบสำหรับปรับ UI อื่นใน **Kestrel** และ **Last Dock** ให้ผู้เล่นเห็นข้อมูลสำคัญ รู้ว่าต้องทำอะไรต่อ และอ่านได้ทันในจังหวะเล่นจริง ใช้สมุดที่อนุมัติเป็นจุดอ้างอิงและแก้เฉพาะ UI เป้าหมายในแต่ละรอบ

## งานรอบนี้

- **หน้าจอที่จะทำ** — [ระบุจุดเอง หรือใช้ชุด UI ในเส้นทางหลักด้านล่าง]
- **จุดที่ต้องแก้ข้อความหรือไฮไลต์เป็นพิเศษ** — [เช่น แยก “อากาศรั่ว” ออกจากข้อความอธิบาย และเน้นห้องที่ต้องไป]
- **ส่งงานแบบไหน** — [ลงมือใน Unity / ลงมือพร้อมบิลด์ Windows / ภาพร่าง] หากเว้นว่าง ให้ลงมือใน Unity และส่งภาพที่ตรวจจากเกมจริง

หากไม่ได้ระบุหน้าจอ ให้ตรวจ UI ที่ผู้เล่นเจอในเส้นทางหลักตั้งแต่เริ่มจนจบทั้งสองด่าน เริ่มที่ **ป้าย E, โจทย์ภารกิจ, คำเตือนและช่วงอพยพ** แล้วตามด้วยคอนโซลสถานี แผงไฟและเครื่องจักร กล่องบทสนทนาและคำใบ้ มื้อเย็น หน้าพัก ตั้งค่า และผลลัพธ์ ปรับทุกจุดที่อยู่ในขอบเขตนี้ตามบริบทของหน้าจอ รวมถึงข้อความที่ซ้ำกันระหว่างป้าย คอนโซล และหน้าภารกิจ

## ภาษาภาพ

ให้ UI ดูเหมือนอุปกรณ์ที่ลูกเรือใช้จริงในโลกการ์ตูนไซไฟของเกม กรอบเขียวอมฟ้ามีขอบหมึกเข้ม มุมตัด และรายละเอียดฮาร์ดแวร์เฉพาะจุด พื้นครีมเป็นพื้นที่อ่าน ตัวเลขและคำสั่งมีน้ำหนักชัด ไอคอนใช้รูปทรงเรียบที่อ่านได้แม้ย่อขนาด ให้ฉากเกมยังเป็นจุดสนใจระหว่างเดิน

| สีจากต้นแบบ | ใช้กับ |
| --- | --- |
| `#396D64` / `#79AB95` | ตัวกรอบเขียวอมฟ้าและขอบรับแสง |
| `#17302F` / `#203F3C` | พื้นคอนโซลเข้มและแผงย่อย โดยใช้ตัวอักษรสีอ่อนบนพื้นเข้ม |
| `#FFEBCA` / `#FFF2DA` | หน้ากระดาษและการ์ดข้อมูล โดยใช้หมึกเข้มบนพื้นครีม |
| `#101A18` / `#5C4C38` | ขอบ ตัวอักษรหลัก และข้อความรองบนพื้นครีม |
| `#FFB53C` | แท็บที่เลือก ปุ่มหลัก ป้ายปุ่มกด และส่วนที่เติมของมาตรวัด |
| `#70B282` / `#E56B40` | ปกติหรือสำเร็จ และอันตรายหรือวิกฤต ใช้คู่กับคำหรือสัญลักษณ์ |

- ใช้กรอบใหญ่และฉากหลังมืดกับหน้าที่ต้องอ่านหรือเลือกหลายอย่าง ใช้การ์ดคอนโซลกับงานซ่อมหรือจัดการทรัพยากร ใช้ป้ายสั้นชิดวัตถุสำหรับ **E** และแถบกะทัดรัดสำหรับเหตุฉุกเฉิน
- ใช้รูปทรงสมุดและสันพับกับหน้าที่มีลำดับหน้าจริง ป้ายคีย์และหน้าต่างสั้นใช้ขอบ สี และไอคอนร่วมกันได้โดยใช้รูปทรงตามงาน
- เรียง **สิ่งที่ต้องรู้ตอนนี้ → สิ่งที่ทำได้ → ต้นทุนหรือผลที่จะเกิดขึ้น** วางข้อมูลที่ต้องเทียบไว้ติดกัน ใช้ช่องว่างจัดกลุ่ม และใช้แถบวัดเฉพาะค่าที่การมองสัดส่วนช่วยตัดสินใจ
- ทำไอคอนเป็นภาพการ์ตูนสีอำพัน ขอบและเงาหมึกดำ ใช้โครงเดียวกับไอคอนมาตรวัด วิทยุ กระเป๋า และทรัพยากรที่มีอยู่ ใช้สีอื่นเมื่อไอคอนต้องสื่อสถานะ ใช้ชื่อหรือคำกำกับกับไอคอนที่อาจตีความได้หลายแบบ
- ทำปุ่มให้เห็นความต่างระหว่างปกติ โฮเวอร์ โฟกัส เลือกอยู่ และกดไม่ได้ ใช้เส้นขอบ รูปร่าง หรือคำกำกับร่วมกับสี ตรวจว่าโฟกัสจากคีย์บอร์ดเห็นชัด และมีคำอธิบายสั้นเมื่อผู้เล่นต้องแก้เงื่อนไขก่อนกด

## ฟอนต์และการแสดงภาษาไทย

- ใช้ฟอนต์ชุดเดียวกับสมุด M ทั้งไทยและอังกฤษ ใช้ **Titan Gate UI Regular** สำหรับเนื้อหา และ **Titan Gate UI Bold** สำหรับหัวข้อ ปุ่ม ข้อความที่เน้น และตัวเลข ไฟล์อยู่ใน `Assets/Resources/Fonts/TitanGateUI-Regular.ttf` และ `TitanGateUI-Bold.ttf` ชุดนี้สร้างจาก Chakra Petch และจัดสระกับวรรณยุกต์ที่เคยซ้อนกันไว้แล้ว
- ใช้ `GameUI.L` และ `GameUI.B` เป็นทางหลักเพื่อใช้ฟอนต์และ Advanced Text Generator ชุดเดียวกัน ใช้ `GameUI.Thai` กับข้อความที่อัปเดตตรงใน `label.text` รวมถึงตัวเลขที่ต่อท้ายข้อความ คำเตือน และคำแนะนำที่เปลี่ยนตามเกม
- เก็บข้อความใน Localization เป็น Unicode ปกติ รักษา placeholder เช่น `{0}` และหน่วยจริง ประกอบประโยคที่แปลครบแล้วจึงส่งเข้า `GameUI.Thai` ให้การแก้สระและวรรณยุกต์เกิดเฉพาะตอนแสดงผล
- ตัดบรรทัดและทำแอนิเมชันพิมพ์ข้อความโดยรักษากลุ่มอักขระไทยทั้งกลุ่ม ตรวจ “น้ำ”, “ที่นี่”, “เชื้อเพลิง”, “อุณหภูมิ” และ “กระป๋องดูดซับ CO₂” ในตัวเกม ทั้งตัวปกติ ตัวหนา และข้อความที่มีไฮไลต์ ถ้าพื้นที่ไม่พอ ให้เพิ่มพื้นที่หรือตัดคำซ้ำโดยคงความหมาย

## เขียนข้อความให้ผู้เล่นลงมือได้

1. รวบรวมข้อความจริงจากหน้าจอเป้าหมาย แยกสิ่งที่ผู้เล่น **ต้องรู้ตอนนี้** จากสิ่งที่อ่านเพิ่มได้ ตรวจชื่อห้อง เป้าหมาย เวลา ต้นทุน เงื่อนไข และผลลัพธ์กับระบบเกมก่อนย่อ
2. ขึ้นต้นภารกิจและปุ่มด้วยกริยาที่ตรงกับผลของการกด ใช้ชื่อที่ผู้เล่นเห็นในแผนที่หรือบนคอนโซล ป้ายสั้นใช้กริยากับสิ่งที่โต้ตอบ ภารกิจใช้หนึ่งบรรทัดหลักและบรรทัดรองเมื่อจำเป็น คำเตือนบอกเหตุแล้วบอกวิธีรับมือ
3. ตัดคำเกริ่น คำชม คำสั่งที่ซ้ำกับปุ่ม และคำอธิบายที่แค่ทวนตัวเลข คงรายละเอียดที่ทำให้ตัดสินใจได้ เช่น **ใช้อะไหล่ 1**, **ทำที่ห้องสื่อสาร**, หรือผลที่ย้อนกลับไม่ได้ บทสนทนาเก็บเสียงของตัวละครและข้อเท็จจริงที่เรื่องต้องใช้ ให้หนึ่งบรรทัดพูดหนึ่งเรื่อง
4. เขียนไทยให้อ่านเป็นธรรมชาติ และแปลอังกฤษตามเจตนาของประโยค ใช้คำเดิมต่อเนื่องทั้งป้ายและสมุด เช่น “ส่งพิกัด / Send location”, “ห้องสื่อสาร / Communications”, “ช่องเทียบท่า / Docking port” และ “อะไหล่ / Parts” ถ้าแก้ `strings.json` ให้แก้ต้นทางใน `tools/strings_src.py` หรือไฟล์ที่สคริปต์นำเข้า แล้วสร้างตารางใหม่ ใช้แหล่งข้อความเดิมในจุดที่มีระบบแปลอยู่แล้ว

ตัวอย่างด้านล่างแสดงวิธีเขียน ตรวจชื่อและตัวเลขกับเกมก่อนนำไปใช้

## ไฮไลต์คำสำคัญและภารกิจ

- เลือกจุดนำสายตาหนึ่งจุดต่อป้ายหรือการ์ด เช่น **การกระทำถัดไป**, **ชื่อห้องที่ต้องไป**, **ค่าใช้จ่าย**, หรือ **คำเตือน** ใช้ Titan Gate UI Bold ประกอบกับสีอำพัน ขอบการ์ด หรือไอคอน เมื่อทั้งประโยคสำคัญให้เน้นทั้งบรรทัดสั้น ๆ
- ภารกิจปัจจุบันใช้แถวที่เห็นชัด พร้อมชื่อการกระทำและความคืบหน้าจริง งานสำเร็จใช้เครื่องหมายถูกและคำหรือสถานะที่อ่านได้ งานที่ติดเงื่อนไขแสดงเหตุผลใกล้ปุ่ม เหตุฉุกเฉินใช้สีแดงอมส้มกับสัญลักษณ์และชื่อเหตุการณ์ ให้ผู้เล่นแยกความหมายได้แม้มองสีไม่ออก
- บนพื้นครีมใช้ข้อความหมึกเข้มกับพื้นหรือขอบที่เน้น บนพื้นเข้มเลือกสีสว่างที่อ่านได้ ข้อความไฮไลต์ต้องยังอ่านออกเมื่อฉากข้างหลังเปลี่ยนสว่างหรือมืด
- ครอบไฮไลต์ทั้งคำหรือวลีให้ครบกลุ่มอักขระไทย ใช้แถวภารกิจ ป้ายย่อย หรือ Label ตัวหนาที่มีอยู่ หากใช้ Rich Text ให้ตรวจว่าฟอนต์ที่เรนเดอร์เป็น Titan Gate UI จริงและเครื่องหมายไทยไม่จมเมื่อเปิดไฮไลต์
- ใช้ไฮไลต์ชั่วคราวเมื่อเป้าหมายเปลี่ยนหรือมีเหตุใหม่ ให้คำเตือนเร่งด่วนขึ้นก่อนข้อมูลปกติ ใช้จุดแสดงภารกิจเดิมที่เหมาะกับจังหวะเล่นและเก็บรายละเอียดไว้ในสมุด M

## การเคลื่อนไหวและการควบคุม

- ให้การขยับบอกว่าหน้าจอเปิดแล้ว สิ่งใดถูกเลือก หรือคำสั่งสำเร็จ ใช้ไอคอนโยกหรือยกเล็กน้อยหลังเลือก ใช้โฮเวอร์สั้น ๆ กับปุ่ม และใช้เฟดหรือเลื่อนช่วงสั้นกับป้ายและการ์ดขนาดเล็ก
- สำหรับหน้าที่เป็นส่วนหนึ่งของ **สมุด M** ให้ใช้แอนิเมชันเดิม ฝาพับเปิดประมาณ **0.76 วินาที** และพับปิด **0.72 วินาที** ไปข้างหน้าพลิกจากขวาไปซ้าย ย้อนกลับพลิกจากซ้ายไปขวา พลิกหนึ่งใบประมาณ **0.60 วินาที** และข้ามสองแท็บให้ผ่านสองใบต่อเนื่องประมาณ **0.48 วินาทีต่อใบ** ใช้ปุ่มและแท็บที่มีอยู่
- รองรับการกดซ้ำ การเปลี่ยนใจระหว่างเคลื่อนไหว และการปิดกลางทาง ให้ UI จบตามคำสั่งล่าสุดโดยรับอินพุตต่อได้ ใช้ตัวเลือก **Reduced Motion** เดิมสำหรับเปลี่ยนทันทีหรือเฟดสั้น
- ใช้ปุ่มตามบริบทของเกม เช่น **M** เปิดสมุด **E** โต้ตอบ **Esc** ปิดหน้าต่างหรือเปิดเมนูพักตามหน้าปัจจุบัน เมื่อเป็นหน้าต่างที่บล็อกฉาก ให้คุมโฟกัส จัดลำดับ Tab และคืนการควบคุมเมื่อปิด ตรวจนโยบายหยุดเวลาของหน้าเดิมก่อนเปลี่ยน โดยเฉพาะช่วงอพยพ

## ข้อมูลและการส่งงาน

ก่อนแก้ ให้ตรวจ `AGENTS.md` ถ้ามี สถานะ Git, `docs/AI_HANDOFF.md`, `docs/LASTDOCK_MANAGEMENT.md` และจุดสร้าง UI ที่เกมเรียกจริง ไล่ชุด **หน้าจอ → ทางเข้า → สิ่งที่ต้องสื่อ → แหล่งข้อมูล** แล้วลงมือเป็นกลุ่ม ใช้ UI Toolkit และส่วนประกอบเดิม ผูกการเน้นภารกิจ ตัวเลข ปุ่ม และเงื่อนไขกับข้อมูลจริงหลังทำคำสั่ง เปลี่ยนฉาก หรือโหลดเซฟ รักษากติกาเกมและงานค้างในเวิร์กสเปซ

ตรวจทางเข้าปกติทั้งไทยและอังกฤษที่ **1280×720** และ **1920×1080** รวมถึงขนาดตัวอักษรที่เกมให้เลือก ตรวจการตัดบรรทัด สระและวรรณยุกต์ทั้งข้อความปกติและไฮไลต์ ความต่างระหว่างสถานะ และอินพุตเมาส์กับคีย์บอร์ด ทดสอบกรณีที่เกี่ยวข้อง เช่น ของหมด กดซ้ำ ค่าเปลี่ยน โหลดเซฟ หรือมีเหตุฉุกเฉิน ส่งภาพจากเกมจริงของหน้าจอที่แก้ ตัวอย่างข้อความก่อน–หลังจุดสำคัญ ผลตรวจ และพาธตัวบิลด์เมื่อขอให้บิลด์
